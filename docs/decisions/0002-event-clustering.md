# 0002 事件聚类：标题相似度 + SimHash + 实体冲突门控

- 状态：已采纳（M2）
- 日期：2026-10-22
- 相关：`src/qf_wire/core/cluster.py`、`src/qf_wire/core/deduper.py`

## 背景

同一事件常被多家媒体用不同措辞报道。M1 只按 URL / 标题指纹去重，无法把“TSMC starts mass production…”与“TSMC begins mass production…”折叠为同一事件，看板与时间线因此碎片化。

## 决策

1. 标题归一化（去标点、转小写）后取字符 bigram，计算余弦相似度，阈值 `0.56`；
2. 64 位 SimHash 作为补充：SimHash 相似度 ≥ `0.86` 且余弦 ≥ `0.30` 时视为同一事件；
3. 规则实体提取机构、产品代号与引号短语；两边都识别出机构且集合不相交时，禁止合并；
4. 只在 7 天窗口内比较，避免历史事件被反复吸附；
5. `event_id = stable_hash(topic, 标题指纹或规范 URL)`，重建后保持稳定；
6. 同一事件 ≥2 个来源时 `confidence=high`，时间线按 `published_at` 升序。

## 理由

- 字符 bigram 不依赖分词，中英文标题都能工作，且比词袋更能抵抗语序变化；
- SimHash 补足长标题中局部改动导致的余弦下降；
- 实体冲突门控解决“同一模板 + 不同公司”的高相似误合并（如两家厂商财报）；
- 稳定 id 让 CLI、看板、MCP 与跨日归档可以引用同一事件。

## 被否方案

| 方案 | 否因 |
| --- | --- |
| 纯编辑距离 | 对长标题与插入形容词敏感，阈值难统一 |
| 向量模型聚类 | 需额外模型依赖与推理成本，违背本地轻量约束（可在 M3 评估） |
| 仅按实体聚类 | 抽取规则覆盖有限，同类事件容易过度合并 |

## 代价与风险

- 固定阈值对某些语言/站点可能偏松或偏紧，需要真实数据回归后调参；
- 实体别名表是规则维护的，新机构需补充；
- 7 天窗口外同一事件的后续进展会形成新事件，符合“日更资讯”的产品语义。
