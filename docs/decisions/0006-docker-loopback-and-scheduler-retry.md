# 0006 容器发布面与调度重试策略

- 状态：已采纳（M4）
- 日期：2026-10-23
- 相关：`docker-compose.yml`、`Dockerfile`、`.dockerignore`、`src/qf_wire/core/jobs.py`、`src/qf_wire/web/server.py`、`tests/unit/test_compose_config.py`、`docs/DEPLOYMENT.md`

## 背景

本机直接运行时，看板天然只监听回环，鉴权默认也按回环放行。进入 Docker 后有两处规则会失真：容器内必须监听 `0.0.0.0` 才能被宿主机端口映射访问；而请求在容器里看到的对端地址是 Docker 网桥网关（私网 IP），不再是 `127.0.0.1`。同时，容器里看板与调度同进程运行，任务失败后的重试行为需要一条明确、可预期的默认值。需要决定：宿主机端口如何发布、MCP 是否一并暴露、容器内如何通过回环鉴权，以及调度失败的重试边界。

## 决策

1. **宿主机只发布回环地址**：compose 的端口映射固定为 `127.0.0.1:8790:8790`，容器内仍监听 `0.0.0.0`。外部机器无法直接连接带标签的端口，与“数据不出本机”一致。
2. **容器只跑看板，不跑 MCP**：compose 不映射 8791，容器内也不启动 `qfw mcp http`。需要 MCP 时在宿主机以进程方式运行，避免凭空多一个对外服务面。
3. **镜像不含用户数据与密钥**：`Dockerfile` 只复制代码、默认配置模板与 prompts；`./data`、`./config` 通过卷挂载。`.dockerignore` 排除 `data/`、`.env*`、`*.db`，保留 `.env.example`。
4. **容器场景显式放开私网，安全性由发布面兜底**：compose 默认 `QF_WIRE_ALLOW_PRIVATE_NETWORK=true`，让 Docker 网桥来访的请求通过鉴权层。因为宿主机端口只绑定回环，这个开关不会把服务暴露给外部网络；如果改用非回环发布，必须自行承担 token 与 TLS 配置。
5. **健康检查带可选 Bearer**：healthcheck 请求 `/api/health`，读取容器内 `QF_WIRE_API_TOKEN`，非空时附加 `Authorization: Bearer`，兼容 `QF_WIRE_API_REQUIRE_TOKEN=1` 的强制鉴权场景。
6. **强制鉴权覆盖健康检查**：设置 `QF_WIRE_API_REQUIRE_TOKEN=1` 时，`/api/health` 与 `/data.js` 都需要 token，不再豁免。默认（未强制）时 `/api/health` 保持公开，便于反向代理与容器探活。
7. **调度失败默认重试一次**：`options.retries` 默认 1，`retry_delay` 默认 5 秒，上限 5 次；`WireError`（配置/参数类错误）不重试，直接记为失败。失败详情写入日志，调度器继续运行后续任务。
8. **重试只发生在单次触发内**：不对失败任务做跨轮补偿；错过触发窗口由 `misfire_grace_time=3600` 决定是否补跑，堆积由 `coalesce=true` 合并。

## 理由

- 端口发布面是容器安全边界里最容易被误改的一处，把它写成固定回环，比在文档里提醒更可靠；
- 容器内监听 `0.0.0.0` 是端口映射的前提，而私网放行是针对网桥地址的最小必要让步，两者叠加后实际可达面仍只有本机；
- 不映射 8791，避免“一键部署”顺带暴露一个额外协议服务；
- 健康检查兼容强制鉴权，避免用户在收紧鉴权后容器一直 unhealthy；
- 配置类错误重试不会自愈，只会放大日志与等待，因此与瞬时错误区分处理。

## 被否方案

| 方案 | 否因 |
| --- | --- |
| 默认发布 `0.0.0.0:8790` | 直接破坏“默认仅本机”的硬约束，外部可访问看板与只读 API |
| 容器内监听 `127.0.0.1` | 端口映射无法到达容器内回环，看板不可用 |
| 把容器网桥地址加入回环白名单 | 混淆“本机”语义，等于对所有容器内请求免鉴权，边界不可审计 |
| compose 同时映射 8791 暴露 MCP | 一键部署不应默认多出一个服务面；MCP 按需在宿主机启动 |
| 对失败任务无限重试 | 配置错误无法自愈，会持续占用调度线程并淹没日志 |
| 强制鉴权仍豁免 `/api/health` | 与“全部鉴权”的要求矛盾，探活可用带 token 的 healthcheck 满足 |

## 代价与风险

- 容器内看到的客户端地址是网桥网关，`QF_WIRE_ALLOW_PRIVATE_NETWORK=true` 属于默认放宽；若有人把端口映射改成非回环，放行范围会随实际网段扩大，必须在变更时同步收紧；
- 调度重试只覆盖瞬时异常，跨轮失败仍需依赖日志告警与人工介入；
- 健康检查读取 token 依赖 shell 展开，镜像内无 `curl` 时改用 Python 标准库实现，写法比 `curl` 啰嗦；
- 不映射 8791 意味着容器内的 MCP 不可用，需要 MCP 的用户必须额外在宿主机运行进程。
