# 0009 聚类阈值配置化与归并依据可解释

- 状态：已采纳（M2 增量）
- 日期：2026-10-24
- 相关：`src/qf_wire/core/cluster.py`、`src/qf_wire/config/loader.py`、`src/qf_wire/storage/sqlite.py`、`src/qf_wire/pipeline/render.py`、`config/digest.yaml`、`docs/CONFIG.md`

## 背景

[0002](0002-event-clustering.md) 把阈值写死在 `core/cluster.py`：字符 bigram 余弦 0.56、SimHash 0.86、SimHash 下限 0.30、实体加分 0.08、窗口 168 小时。真实数据跑下来，不同站点/语言对阈值的松紧要求并不一致，调参必须改代码再发版。

同时，看板只显示“同一事件 N 篇报道”，读者看不出这些报道为什么被折叠：是同一链接转载、标题高度相似，还是命中了共同实体。误合并时也无从定位是哪条规则放行。

## 决策

1. 新增 `ClusterSettings`（frozen dataclass），五项阈值作为字段，默认值与原常量一致；`from_mapping` 校验取值范围并拒绝未知字段。
2. `config/digest.yaml` 增加顶层 `cluster:` 段；缺省时沿用内置默认值，配置非法时 `qfw config validate` 与加载阶段都报错。两份 JSON Schema（包内与 `config/schema/`）同步声明该段。
3. 聚类时记录每条合并的**证据**：共同实体、标题余弦、SimHash 相似度，并归类为 `duplicate` / `shared_entity` / `simhash` / `title_similarity`。
4. 事件落盘 `explanation` 列（迁移 `0005_events_explanation`），JSON 序列化后随事件读写；读取失败按“无解释”处理，不阻断历史数据。
5. 解释以人话输出：`qfw event show` 增加“归并依据”，看板事件时间线折叠区显示“归并依据：共同实体：tsmc；标题相似度 0.83”。单篇报道不产生解释。
6. `qfw doctor` 与 `scripts/healthcheck.sh` 作为部署自检面，分别覆盖配置/数据目录/模型网关与运行实例健康。

## 理由

- 阈值进配置后，调参不需要改代码，也不会因误改常量而悄悄影响所有实例；
- 证据与事件同生命周期存储，跨日重建与 CLI/看板/API 读到的是同一份解释；
- 解释字段只增不改语义：旧事件没有解释时显示“未记录”，不做推断；
- 自检命令把“配置能加载、目录可写、模型网关可达、实例在跑”变成一条可脚本化的检查，减少上线后的排查成本。

## 被否方案

| 方案 | 否因 |
| --- | --- |
| 阈值继续留常量 | 调参必须发版，多实例无法差异化 |
| 解释只在渲染时现算 | 看板与 CLI 各算一遍易漂移，且历史事件无法回溯当时的判定依据 |
| 存整段标题相似度矩阵 | 数据量随事件平方增长，收益仅是调试信息 |
| 用模型生成归并解释 | 额外推理成本与不确定性；规则证据已足够回答“为什么归到一起” |

## 代价与风险

- `cluster` 段与包内 Schema 是两份拷贝，新增字段必须同步修改，否则 `config validate` 与运行时行为不一致（已有测试覆盖非法配置）；
- 解释字段记录的是**当时**的判定证据；后续手工合并/拆分不会回写，需以最新一次聚类结果为准；
- 阈值可调意味着不同实例可能对同一批数据产生不同事件边界，跨实例对比数据时需确认配置一致。
