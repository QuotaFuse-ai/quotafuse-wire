# 0003 信源评分：可解释的三项加权 + 低分降级

- 状态：已采纳（M2）
- 日期：2026-10-22
- 相关：`src/qf_wire/core/scorer.py`、`src/qf_wire/storage/migrations/0002_source_scores.sql`

## 背景

信源质量参差。需求要求用“准确率、时效性、重复率”给信源评分，评分要随运行累积、落库，并参与要点可信度。

## 决策

1. 三项分值与权重：
   - 准确率 `accuracy = 被印证条目 / 条目数`，权重 0.5；
   - 时效性 `timeliness = 1 - 同事件首报延迟 / 24h`（裁剪到 0..1），权重 0.3；
   - 独特性 `uniqueness = 独家条目 / 条目数`，权重 0.2；
2. “被印证”指该条目所属事件有 ≥2 个来源，或去重后条目本身合并了多个来源；“独家”为其余情况；
3. 分母为 0 时返回中性分 0.5，避免新源被直接判低分；
4. 计数按运行累加（`runs/items/corroborated/exclusive/timeliness_sum/timeliness_samples`），持久化到 `source_scores` 表；
5. 综合分 < `0.45` 视为低分；低分信源**单独支撑**的要点降级：`high → medium`，其余 → `low`；只要要点还有任一非低分来源，则不降级；
6. 评分写入 `data.js` 的 `sourceScores`，看板展示综合分与分项。

## 理由

- 三项都能从本地采集结果直接计算，无需人工标注或外部数据；
- 权重偏向“被多源印证”，这是最可靠的准确率代理；
- 中性分与保守降级避免冷启动阶段误伤新源；
- 累加计数让评分随运行次数收敛，单日异常不会立刻改变长期评价。

## 被否方案

| 方案 | 否因 |
| --- | --- |
| 人工维护权重表 | 不可扩展，且会引入主观偏差 |
| 用模型判断可信度 | 成本高、不可复现，且违背“可解释”要求 |
| 仅按发稿量排序 | 高产不等于准确，会奖励搬运与重复 |
| 低分信源直接剔除 | 损失独家和早期线索，与“多源感知”目标冲突 |

## 代价与风险

- 准确率是代理指标：被多家转载的错误信息仍会得分，需要后续引入纠错信号；
- 24 小时时效窗口对周报型信源不友好，其时效分会偏低；
- 阈值 0.45 与权重是初始值，应基于真实运行数据回归后再调。
